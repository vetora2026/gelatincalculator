## Reusable patterns (lift these for site #2 and beyond)

### Pattern 1: Cloudflare Pages cache configuration
For any static Astro site on Cloudflare Pages, both of these are required to get healthy edge cache rates:

1. **`public/_headers` file** controlling browser cache:
   - HTML: `Cache-Control: public, max-age=3600, s-maxage=3600, stale-while-revalidate=86400`
   - `/_astro/*`: `Cache-Control: public, max-age=31536000, immutable`
   - Images/fonts: `Cache-Control: public, max-age=31536000, immutable`
   - Favicon: `max-age=86400`
   - robots.txt + sitemap: `max-age=3600`

2. **Cloudflare Cache Rule** (configured in dashboard, NOT code):
   - Name: "Cache HTML at edge"
   - Match: `Hostname equals <site-domain>`
   - Cache eligibility: Eligible for cache
   - Edge TTL: Override origin, 4 hours
   - Browser TTL: Respect origin

## What NOT to do (lessons learned)

- ❌ Do not assume `_headers` alone fixes Cloudflare cache rate — Cache Rule is also required
- ❌ Do not write Privacy policies that say "we don't run ads" if the AdSense script is loaded — match policy to reality
- ❌ Do not let Cloudflare Email Address Obfuscation rewrite contact emails — wrap with `<!--email_off-->`
- ❌ Do not click "Request review" multiple times in AdSense — slows the process
- ❌ Do not diagnose a workflow as broken from a UI banner — read the actual file content first
- ❌ Do not overpromise specific metric outcomes (e.g., "cache rate will hit 80%") — give realistic ranges with assumptions
- ❌ Do not skip the 30-day monitoring window without explicit logged override
